# MindLite UI 预览实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付无需安装依赖、双击即可打开的思维导图 UI 预览，供用户确认视觉和交互。

**Architecture:** 使用 HTML、CSS、原生 JavaScript 和 SVG，所有数据保存在预览页面内存中。将场景、布局、画布交互分离，后续桌面前端复用已确认的视觉；此阶段不接入原生文件命令。

**Tech Stack:** HTML / CSS / JavaScript / SVG，Windows BAT 启动入口。

**Spec:** `docs/需求开发方案.md`（用户已确认）。本计划仅实现方案中的第二阶段；Rust 编辑核心及文件模块另行实施。

## Global Constraints

- 未经用户明确要求不运行测试。
- 第一阶段只交付独立可运行的 UI 预览；用户确认视觉及交互后才实现真实业务。
- 只使用 main，不使用 worktree 或其他分支。
- 不安装新工具，不依赖 CDN、接口、数据库或完整打包流程。
- 当前不是 Git 仓库且没有远端；不猜测仓库地址，不擅自创建 GitHub 仓库。日志如实记录无法同步的原因。

## Review Focus

以下为交付给用户的手动验收重点，开发期间不自动运行测试：

1. 中文输入组合期间，Tab/Enter 不应误触发节点结构操作。
2. 深层节点及长文本应保持可见、可平移，连线跟随布局。
3. 缩放后拖拽的指针位置和落点预览应一致。
4. 空白、加载和错误场景应能返回正常预览，不造成死路。
5. 动画暂停后可继续，重播后回到相同初始状态；窄窗口不能遮挡核心控制。

## 文件职责

- `preview/index.html`：语义化页面壳、文件菜单、画布、布局弹层、底部工具栏、场景与动效控制。
- `preview/styles.css`：白色画布、节点/连线状态、弹层、响应式布局与动效。
- `preview/scenes.js`：全局 `MindLiteScenes`，提供 `createScene(name)` 返回独立 mock 数据，包含 normal/loading/empty/error/edge。
- `preview/layout.js`：全局 `MindLiteLayout`，提供 `layoutTree(root, mode)`，返回节点坐标和边；预览采用固定节点宽度上限及文本换行，子树跨度用于避免重叠。
- `preview/app.js`：内存预览状态、SVG/DOM 渲染、节点交互、工具栏、缩放/平移、模拟反馈与动效。
- `预览MindLite.bat`：通过 Windows 默认浏览器打开同目录的 `preview/index.html`，路径带空格时仍可用。
- `docs/开发日志.md`：记录交付状态及用户待确认项。

使用传统脚本按 scenes → layout → app 顺序加载，保证 file:// 直接打开可用，不依赖模块服务器。

## Task 1：页面壳与场景展示

**Interfaces:** `createScene(name: string) -> {root, status, message}`；节点为 `{id, text, children, collapsed?, bold?, italic?, underline?, done?}`。场景每次返回副本，避免切换后污染初始数据。

- [ ] 创建 index.html 与 styles.css：顶部文件菜单及预览标识、白色画布、左下控制、底部选中节点工具栏；节点和弹层参考四张原图。
- [ ] 实现 scenes.js：普通示例、居中空白根节点、加载提示、可恢复错误、长中文/多分支/深层级场景。
- [ ] 实现 app.js 场景切换与明确的模拟文件菜单反馈，文件菜单不得读写真实文件。
- [ ] 在日志记录本模块完成及待用户验收；不运行测试。

## Task 2：布局、颜色与交互预览

**Interfaces:** `layoutTree(root, mode: 'auto'|'right'|'left'|'down'|'both') -> {nodes, edges}`；每个输出节点包含 `id, parentId, x, y, width, height, branchIndex`，坐标采用节点中心；输入树不被布局函数修改。app.js 将节点状态与坐标关联渲染。

- [ ] 实现 layout.js：根据子树跨度排列，自动平衡左右、左右交替、左、右、下五种布局；折叠时不输出后代坐标。
- [ ] SVG 绘制圆角折线/曲线，DOM 渲染可编辑节点；表现 hover、选中、展开/收起和完成状态。
- [ ] 支持预览内存中的 Tab 子节点、Enter 同级、根 Enter 子节点、Shift+Enter 换行和 Esc 结束；尊重 composition 输入状态。
- [ ] 实现统一色、一级分支色、稳定随机色，提供十二色色板与色号复制反馈；复制失败时允许选中色号手动复制。
- [ ] 实现粗体、斜体、下划线与递归完成预览；取消完成递归取消。所有变化仅保存在 mock 内存中。
- [ ] 实现缩放 25%—300%、Ctrl +/-、Ctrl+滚轮、Ctrl+0、画布平移和居中；页面控制获得焦点时避免劫持常规输入。
- [ ] 提供预览内撤销/重做，覆盖模拟编辑、格式、布局、配色、折叠及移动；缩放和平移不记录。
- [ ] 更新日志；用户验收聚焦中文输入、深层文本和窄窗口，不运行自动测试。

## Task 3：拖拽反馈、动效控制与交付

**Interfaces:** app.js 管理 `{draggedId, origin, pointer, targetId}` 拖拽临时状态，落点使用画布逆变换坐标；不允许向自己或后代挂接。动画以统一 `paused` 状态控制，重播恢复固定 mock 场景。

- [ ] 拖拽显示原节点轮廓、透明子树与虚线目标框；松手更新 mock 位置或挂接，Esc 取消。切换布局清除手动偏移。
- [ ] 添加显式演示动作、暂停/继续和重播按钮，让用户无需真实文件即可重复观察反馈。
- [ ] 创建 `预览MindLite.bat`；无需 EXE 即可通过独立 HTML 交付本阶段，避免提前搭建业务壳。
- [ ] 使用只读文件检查确认交付入口和脚本引用存在；不运行应用测试或自动浏览器检查，不将未验证行为描述为已通过。
- [ ] 更新开发日志，记录预览路径、使用方式、未实现的真实文件操作以及待确认视觉/交互。
- [ ] 向用户交付预览，等待 UI 确认后再实施 Rust 桌面和文件业务。

## 后续阶段边界

本阶段不生成正式 MindLite.exe，不实现 .mindlite/.mm 解析、磁盘保存或图片文件导出。正式应用继续采用已确认的 Rust + Tauri + WebView2 方案；用户测试 EXE 统一覆盖 `dist/MindLite.exe`，覆盖前终止旧进程。
